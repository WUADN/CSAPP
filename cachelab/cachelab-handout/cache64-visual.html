64x64 为什么要把 8x8 再拆成 4x4

这个页面把 Cache Lab 的直接映射缓存画出来：32 个 set，每个 cache line 是 32B，正好放 8 个 int。 对 64x64 矩阵，连续一行有 64 个 int，也就是 8 条 cache line，因此 set 编号每 4 行重复一次。

cache line: 32B = 8 个 int
64 个 int/行 = 8 条 cache line
set = (row * 8 + col / 8) mod 32
第 0 行和第 4 行会落到同一组 set

直接映射缓存：同一个 set 只能留下一个 cache line

A 的 cache line B 的 cache line 本步发生驱逐

普通 8x8 的问题

读一行 A 后，8 次写 B 会碰到 B 的第 0/4、1/5、2/6、3/7 行落在相同 set 的情况。 临时变量只保存了值，保存不了 B 的 cache line，所以 B 自己也在来回挤掉自己。

4x4 拆分的意义

先只碰 B 的上 4 行，它们分别占 set 0、8、16、24，不互相冲突。 右上角先借 B 的空位暂存，再和左下角交换，避免在还需要复用时立刻碰 B 的下 4 行。
